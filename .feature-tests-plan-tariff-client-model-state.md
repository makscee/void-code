# Feature-test plan: authoritative client Codex model decision state

## Contract under test

A pure, client-local reducer owns only Codex catalog/selection authority for one local session/device. It consumes (a) an atomic server decision bundle observed over a measured monotonic request/response interval, (b) a local Codex selection attempt, or (c) a monotonic lease check. It never fetches, renders, registers a provider, calls Pi, or owns any non-Codex state.

The reducer must:

- compare decimal generation strings exactly and apply authority only when generation is greater;
- ignore lower generations; treat equal generation as idempotent only when every authority field and ordered catalog is identical; fail closed on an equal-generation authority conflict;
- validate and replace a bundle atomically, never combining revisions/catalog fields from different generations;
- derive `leaseExpiresAt` only from `validUntil-evaluatedAt-observedRTT-skewGuard`, anchored at the monotonic response instant; reject a non-positive lease and empty choices exactly at expiry;
- require a non-empty, unique ordered allowlist and a default contained in it;
- constrain current/fallback choices to the server allowlist/default (no hard-coded model fallback);
- remember the local pre-restriction model only on unrestricted→restricted, reject forbidden local attempts without changing that memory, and restore it on restricted→unrestricted only if the new allowlist still permits it;
- otherwise select the current server default, including T1 removal of stale Astra and a later downgrade that invalidates remembered Astra;
- keep each reducer instance's remembered preference independent.

## Test seam specified by the RED suite

The production lane is expected to provide these package-local pure values in `cmd/vc`:

- `newPiModelDecisionState(currentCodexModelID string) piModelDecisionState`
- `reducePiModelDecision(state piModelDecisionState, event piModelDecisionEvent) piModelDecisionState`
- event kinds for atomic server bundle, local Codex selection, and monotonic lease check;
- bundle/state fields used by `cmd/vc/pi_model_decision_test.go`.

Generation remains a decimal string so values above JavaScript's safe integer range cannot collapse. Server timestamps may be represented as `time.Time`, but are used only for subtraction; all local deadlines/checks are monotonic `time.Duration` values. The result state is the observable reducer output: generation, authority metadata, ordered allowed IDs, default, restriction flag, selected Codex model, and monotonic lease deadline. Remembered preference is tested only through later restoration, not by inspecting private memory.

## Determinism and oracles

- No sleeps, wall-clock reads, filesystem, home directory, network, or production endpoints.
- Fixed server instants are used only to calculate durations; local observations and expiry checks use explicit monotonic durations.
- Expected catalogs, selected model, metadata, and lease deadlines are independently stated from the normative formulas.
- The permutation test uses a fixed exhaustive set of six orderings, no random seed or dependency.

## Mutation targets

The suite is designed to kill: `>`→`>=` generation application, lexical/float generation comparison, lower-generation overwrite, partial field merge, order-insensitive equal comparison, equal-conflict fail-open, omitted default/empty/duplicate validation, omitted RTT or skew subtraction, `<` vs `<=` expiry, hard-coded Luna fallback, remembering a forbidden fallback attempt, subject-global memory, unconditional stale-Astra restore, and restore-before-new-catalog validation.

Mutation/coverage scoring is deferred until the implementation actor makes the RED suite compile; this commit must remain RED by design.

## Contract interpretation (non-contradictory)

An equal-generation response with identical authority is permitted to renew the monotonic lease because tier §4 requires identical authority at equal generation and separately says every fetch arms a lease. `evaluatedAt`/`validUntil` are lease evidence rather than mutable catalog authority. A zero remaining lease is expired: the formula clamps at zero and the same section requires choices to empty at lease expiry. No test assumes whether an invalid greater bundle persists its generation watermark; the observable required result is fail-closed emptiness, avoiding an unstated recovery policy.
